# Мої фінанси

Самодостатній навчальний застосунок для особистих фінансів українською мовою. Написаний на HTML, CSS і звичайному JavaScript. Сервер, обліковий запис і встановлення пакетів не потрібні. Інтерфейс і назва є власними; застосунок не пов’язаний із BudgetBakers.

## Запуск

Відкрий `index.html` у сучасному браузері. Усі HTML, CSS і JavaScript-файли мають залишатися в одній папці; збірка та встановлення пакетів не потрібні. Навігація працює звичайними відносними посиланнями між файлами. Для збереження доступу до старих даних відкривай оновлений проєкт з того самого шляху та в тому самому браузері: `localStorage` прив’язаний до походження сторінки.

## Сторінки й навігація

| Адреса | Вміст |
| --- | --- |
| `index.html` | Місячний огляд і загальна сума витрат за весь час окремо за валютами |
| `transactions.html` | Додавання, історія, пошук і фільтри операцій |
| `planning.html` | Бюджети, цілі, регулярні операції та правила |
| `management.html` | Рахунки, категорії та підкатегорії |
| `data.html` | Імпорт, експорт, резервні копії та тема |
| `registration.html` | Демонстраційна форма реєстрації |
| `category.html?id=ID` | Деталі конкретної категорії витрат |

Шапка кожної сторінки містить посилання на основні розділи й позначає активний. Посилання на категорії є в огляді, керуванні категоріями та історії операцій. ID береться зі збереженої категорії; невідомий або видалений ID показує повідомлення з переходом до списку категорій. Сторінка категорії показує витрати за обраний місяць і за весь час, історію, підкатегорії та пов’язані бюджети.

## Дані та обмеження

- Дані зберігаються в `localStorage` поточного браузера під ключем `my-finances-v2`. Паролі й дані демонстраційної форми реєстрації не зберігаються.
- Формат даних має версію 3. Попередній формат версії 2 автоматично та без видалення записів оновлюється при відкритті: наявні рахунки, операції, бюджети й цілі отримують UAH. Резервні копії обох версій можна відновити.
- Усі сторінки використовують ту саму модель і ключ сховища. Переходи між ними не мігрують і не очищають дані. Демонстраційна реєстрація не надсилає даних у мережу.
- Під час першого відкриття цієї версії застосунок один раз додає 12 прикладів витрат із реалістичними сумами (заправка, кафе, магазин, аптека, кіно та інші). Це працює і для вже наявних даних: вони залишаються, приклади не дублюються. Якщо видалити приклад, він не з’явиться знову після перезавантаження. У списку витрати показуються зі знаком мінус.
- Спосіб розрахунку й рахунок — різні поля: рахунок визначає, звідки списуються гроші, а спосіб розрахунку описує, як саме ти заплатив. Доступні готівка, картка, банківський переказ, телефон або годинник, онлайн-оплата, електронний гаманець та «Інше». Старі операції без цього поля показуються як «Не вказано».
- Каталог категорій розширено; він охоплює продукти, кафе, пальне, таксі, аптеку, кіно, комунальні послуги, підписки, освіту та інші потреби. Батьківський бюджет і фільтр враховують підкатегорії. Уже збережені категорії не змінюються, нові додаються один раз.
- При міграції старий ключ `expense-tracker-v1` не видаляється. Старий формат не мав дати операції, тому перенесеним витратам призначається дата першої міграції. Новий формат зберігається окремо.
- Суми ведуться в цілих сотих одиниці валюти. Кожен рахунок має тип (готівка або банк / картка) і валюту UAH, EUR чи USD. Можна створити, наприклад, «Готівка · EUR» і «monobank · EUR». Огляд і сторінки категорій показують підсумки окремо за валютами. Суми різних валют не додаються. Бюджет і ціль теж мають валюту; бюджет рахує лише витрати в ній.
- Для переказу між рахунками однієї валюти сума списання дорівнює сумі зарахування. Якщо валюти різні, введи обидві суми; застосунок показує курс саме цієї операції, але не підставляє ринковий курс автоматично. Валюту рахунку з балансом або операціями не можна змінити: створи інший рахунок і переказ, щоб не переозначити старі суми.
- Під час імпорту CSV назва, сума й дата обов’язкові. Валюта старого CSV без валютних колонок вважається UAH. Для валютного переказу потрібні валюта рахунку отримувача й сума зарахування. CSV експорт містить обидві суми та валюти. Якщо колонки рахунку чи категорії не зіставлені, беруться перший активний рахунок відповідної валюти й перша категорія відповідного типу. Невідомі рахунки, категорії, способи розрахунку та очевидні повтори пропускаються. Підтримуються CSV із комою або крапкою з комою як розділювачем. Дата має формат `РРРР-ММ-ДД`, сума — додатне число з не більш ніж двома десятковими знаками.
- Регулярні операції не створюються без дії користувача. Кнопка «Підтвердити» створює один запис на заплановану дату і пересуває наступну дату; «Пропустити» лише пересуває дату.
- Цілі заощадження мають ручний прогрес і не змінюють баланс рахунків. Бюджети рахують витрати за обраний період.
- У разі недоступного сховища або нестачі місця сторінка показує помилку. Для захисту від втрати даних регулярно створюй резервну копію JSON.

## Тести

Потрібен Node.js. Запуск без залежностей:

```powershell
node script.test.js
node finance.test.js
node pages.test.js
node --check script.js
node --check finance.js
node --check app.js
```

Тести перевіряють стару логіку домашнього завдання, міграцію версії 2 у 3, окремі валютні баланси, валютні перекази, бюджети, точність сум, фільтри, повторення дат, резервні копії, CSV, посилання категорій і структуру сторінок. У браузері варто додатково пройти навігацію й кнопку «Назад», пряме відкриття сторінок, додавання операції та звірку сум між сторінками, перезавантаження без повторного додавання прикладів, екран невідомої категорії, мобільний макет і клавіатуру.

## Структура

- `index.html`, `transactions.html`, `planning.html`, `management.html`, `data.html`, `registration.html`, `category.html` — окремі сторінки; сторінка категорії використовує один шаблон і параметр `id`.
- `style.css`, `enhancements.css` — основне та додаткове адаптивне оформлення.
- `finance.js` — модель даних, міграція та чисті розрахунки.
- `app.js` — спільні функції відображення, форм, подій, сховища й імпорту/експорту; ініціалізація залежить від сторінки.
- `script.js` — демонстраційна форма реєстрації та сумісність із початковими тестами.
- `script.test.js`, `finance.test.js`, `pages.test.js` — автоматизовані тести.

## Що потрібно для зовнішніх інтеграцій

Банківська синхронізація потребує ліцензованого провайдера Open Banking, серверної частини, захищеного зберігання токенів, згоди користувача й перевірки вимог провайдера. Справжня авторизація, спільний доступ і синхронізація між пристроями потребують сервера, бази даних, керування ролями та захисту приватних фінансових даних. OCR чеків потребує дозволу на фото, обробки зображень і перевірки розпізнаних сум. Актуальні котирування й курси потребують джерела даних із чіткою датою оновлення. Жодна з цих інтеграцій не імітується в локальній версії.

Наступний технічний етап: спершу вирішити, чи потрібна справжня багатокористувацька синхронізація; лише після цього обирати серверну архітектуру й провайдерів інтеграцій.
